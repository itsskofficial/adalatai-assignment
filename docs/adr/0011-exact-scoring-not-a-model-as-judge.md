# The eval scores by exact match, in our own harness, with no model as judge

Every answer the tool produces has one right value: an email is an invoice or it is not, a total is 652.50 or it is not. The sample invoices are generated by us, so the right value is known for each. The eval therefore compares each answer with the known one and needs no model to judge it. We wrote the harness ourselves and did not adopt an evaluation library such as DeepEval.

## Considered Options

- **An evaluation library built around a model as judge** (DeepEval and similar): rejected. Its strength is scoring outputs that have no single right answer, such as whether a reply is relevant or faithful. We have no such outputs. A judge would add a model call per item, would give a different score on a different day, and could itself be wrong about what is correct.
- **Our own harness with exact scoring**: chosen.

## Consequences

The same inputs give the same scorecard every time, so a fall in accuracy is a real fall and can fail the build.

"Ask your invoices" is scored the same way. The model's only job there is to choose a query and its parameters (ADR 0007), which either match the expected ones or do not.

If the tool ever produces free text that a person reads, such as a written explanation of an anomaly, this decision is to be revisited for that output alone.
